```bash
pnpm add github:0froq/ui#v0.1.0
```

锁在 tag 上。库更新之后，项目要自己改这一行才会跟上。

## 引用

字体不在包里。paper 用 Instrument Serif、Geist、Geist Mono，项目自己引。没引就退回系统字体。

```ts
import '@froq/ui/paper/style.css'
import { Choice, Toggle } from '@froq/ui/paper'
```

```vue
<div class="ui-paper">
  <Choice
    v-model="tone"
    label="Tone"
    :options="[
      { value: 'quiet', label: 'quiet' },
      { value: 'loud', label: 'loud' },
    ]"
  />
</div>
```

包里是源码（`.vue`、`.ts`、`.css`），由使用方的构建工具编译。Vite 直接可用。

## Nuxt

这个文档站就是这么接的。`build.transpile` 让 Nuxt 去编译包里的 `.vue`。

```ts
export default defineNuxtConfig({
  css: ['@froq/ui/paper/style.css'],
  build: { transpile: ['@froq/ui'] },
})
```

要三种风格都出现在同一页，把另外两份 `style.css` 也放进 `css`。

## 本地改、先不推

克隆库到本地，在项目的构建配置里用环境变量切过去。这份配置可以提交。线上没有这个变量，始终用锁住的 tag。

```ts
// vite.config.ts
resolve: {
  alias: process.env.UI_LOCAL ? { '@froq/ui': `${process.env.UI_LOCAL}/src` } : {},
}
```

```bash
UI_LOCAL=~/code/ui pnpm dev
```

Nuxt 用同样的做法，写在 `alias` 里，并保留上面的 `build.transpile`。

线上构建看不到本地没推的改动。顺序是：库里提交并打 tag，项目里改版本，再推项目。
